# Market Radar — 30초 흐름 / 재료 종합 / 종목 차트

## 구현 범위

새 `30초 흐름` 탭은 기존 화면과 분리된 관측 데스크다. 누적 거래대금, 실제 수신 간격의 대금 증가액, 약 5분 대금 증가액, 직전 구간들의 초당 거래대금 중앙값 대비 배율, 시가총액과 대금/시총 비율을 보여준다. 표본은 키움 조회순위 + 거래대금 상위 100종목의 합집합이다. 전체 한국 주식시장을 전수 수집하는 것은 아니다.

기존 수집기가 거래대금 순위(stex_tp=3)는 통합으로 받고 종목 상세는 무접미사(KRX)로 받던 범위 불일치를 고쳤다. 상세는 `종목코드_AL`로 받고 별도 `radar_flow_quotes` 테이블에 source, venue, 원시 거래대금/시총, 변환값, 체결시각/일자, 수집시각, 점검 플래그를 보존한다. 예전 데이터는 수정하거나 재계산하지 않는다.

금액 단위는 값의 크기만 보고 추측하지 않는다. ka10095의 원시 거래대금·시가총액을 보존하고, 거래대금은 누적거래량×당일 가격범위, 시가총액은 현재가×상장주식수와 대조해 가능한 단위 스케일을 선택한다. 대조가 풀리지 않으면 금액을 숨기고 품질 플래그를 남긴다. 첫 장중 실행에서 HTS 값과 다시 대조해야 한다. 분봉·일봉 차트는 현재 기존 chart-feed의 KRX 데이터이며 통합 대금과 범위가 다르다는 안내를 표시한다.

## 30초의 뜻

수집 루프는 작업 시간을 뺀 30초 목표 주기, 화면도 30초 목표 갱신이다. API 지연과 제한 때문에 정확히 30초 간격이 보장되지는 않는다. 표에는 실제 두 수신 사이의 초 수가 표시된다. 약 5분 값 역시 300~390초 내 실측 비교이며 외부 체결 스트림으로 30초봉을 직접 만든 것이 아니다.

새 자료 2회 전까지 증가액은 비교 대기다. 속도 배율은 적어도 5개의 이전 유효 구간이 있어야 표시한다. 종목 첫 편입을 누적 거래대금 전체의 신규 유입으로 간주하지 않는다. 거래일 변경, source/venue 변경, 누적값 감소, 관측 누락은 비교 불가로 분리한다.

섹터의 비중 변화는 최신 3개 공통 스냅샷에 연속 관측된 동일 종목 집합으로 계산한다. 현재·이전 분모가 0이면 비중 변화는 미확인이다. 한 종목은 하나의 대표 군에만 배분된다. 분류는 두 구간 모두 현재 대표 분류를 사용해 분류 변경 자체가 자금 이동처럼 보이지 않게 한다.

이 수치는 거래 활동과 거래 집중도다. 매수/매도 주체의 순유입, 순매수, 자금 이체를 측정하지 않는다. 체결시각이 오래되면 새 DB 기록이 있어도 실시간이라고 표시하지 않는다.

## 세부업종과 재료

사업분류(초기 CURATED_V1 또는 공식 업종 fallback), Kiwoom 시장테마 소속, 사건유형을 세 축으로 분리한다. 시장테마는 ka90001(테마그룹별요청)을 종목별로 점진 수집하며, 여러 테마에 속한 종목은 현재 등락이 가장 큰 테마를 대표 표시하되 전체 소속도 상세화면에 남긴다. 테마 소속 자체를 오늘 가격의 원인으로 간주하지 않는다.  초기 운영표에 없는 기업은 `세부 분류 대기`를 유지하며 다른 종목 기사에 등장한 HBM/반도체 키워드로 섹터를 덮어쓰지 않는다. 초기 분류표는 거래소 공식 세부업종 분류나 전종목 분류 완성본이 아니다.

사건유형은 새 외부 AI 보고서의 명시적 `재료분류:` 중 허용된 유형만 사용한다. 수주·공급계약 / 실적·가이던스 / 기술·제품·양산 / 정책·규제 / 승인·임상 / 자본·주주환원 / 업황·가격 / 인수·사업재편 / 기타·미확인이다. 같은 유형은 동일 사건이라는 뜻이 아니다. 보고서가 없거나 분류가 없으면 분석 대기다. 기존 보고서에 없는 새 분류를 기사 제목만으로 만들어내지 않는다.

화면에서는 재료×시장테마 / 시장테마 / 사업 세부업종을 각각 분리해 볼 수 있다. 종목 선택 시 인용을 보존한 핵심 재료 / 새로움과 반복 / 시장 연결 / 반대 근거·미확인을 직접 보여준다. 원문과 공개자료 후보는 접어두고 링크를 제공한다. 작성 6시간 넘은 보고서는 과거 보고서로 표시하고 현재 사건유형 분류에 쓰지 않는다. 6시간 기준은 임의 운영 유효기간이지 사건 소멸의 증명이 아니다.

## 자동 조사

`flow_research_worker.py`는 기존 OpenAI 호출기/DB 원장/잠금/중복 유예/일일·시간당 시도 제한을 그대로 사용한다. 최근 체결이 있고 실제 증가 대금이 있는 종목에서 거래속도 증가, 조회 상위, 대금 상위, 큰 등락, 미분석 상태를 조합해 자동 조사 대상을 고른다. 이는 확률·추천점수가 아니라 내부 작업 우선순위다.

실행 중인 작업기에서 WEB_RESEARCH_AUTO=1과 유효한 키·모델 설정이 있어야 한다. 외부 AI의 실제 권한·잔액·완료 성공은 별도 런타임 검증 대상이다. 기존 키 인증 성공만으로 웹 조사 성공을 주장하지 않는다. 최근 보고서는 다시 쓰고 새 공개자료가 생기면 재검토하되, 이것도 기존 한도 내에서만 처리한다. 뉴스 제목 후보 수집은 별도 저비용 순회(우선종목 5분, 나머지 15분 목표 / 주기당 최대 6종목)이며 AI 종합과 다르다. 공급자 지연 시 주기는 늘어난다.

**하루 1회 설정을 해뒀다면 자동화해도 하루 1회다. 실패 시도도 포함한다.** 이 릴리스는 한도를 늘리거나 실패 기록을 삭제하지 않는다. 전종목을 30초마다 웹 AI로 조사하는 기능은 아니다. 30초 시장 관측과 이벤트 선별 AI 조사는 독립된 주기다.

AI에는 공개 종목 식별자, 시점, 순위, 공개 뉴스 후보, 점검된 단위의 로컬 금액만 보낸다. Telegram 원문/비공개 채널명/계좌/세션/키는 보내지 않는다. 출처가 있어도 사건의 사실성이나 주가 원인이 자동으로 검증되는 것은 아니다.

## 실시간 관찰 후보

30초 흐름 화면 상단에 최대 12개의 **실시간 관찰 후보**를 표시한다. 이는 매수·매도 추천 또는 기대수익률 예측이 아니다. 현재 화면에서 먼저 확인할 종목을 줄이는 로컬 관찰 우선순위다.

후보는 최근 체결이 있고 검증 가능한 구간 거래대금 증가액이 있는 종목만 대상으로 한다. 조회순위, 거래대금 순위, 최근 구간 거래대금 순위, 이전 유효 구간 대비 거래속도, 고정 공통표본의 시장테마 거래비중 변화, 최근 15분 이내 차트 상태, 인용 포함 재료보고서 유무를 합산한다. TREND_DAMAGE, BREAKOUT_FAIL, 테마비중 급감, 당일 과도한 급등, 재료 미검증은 위험/확인 항목으로 분리한다.

표시 레벨은 `관찰 우선 / 조건 확인 / 추적`이며 점수 이름은 `관찰도`다. 점수는 수익 확률이 아니며 주문에는 연결되지 않는다. 카드에서 종목 상세와 3분봉·일봉 차트를 바로 열 수 있다. 후보 계산은 로컬 DB만 사용하므로 30초 갱신 자체는 OpenAI 비용을 추가하지 않는다.

### 후보 유형 4종

실시간 관찰 후보는 동일한 관찰도 순위에 더해 네 가지 이유 유형을 표시한다.

- **추세·돌파**: BREAKOUT_HOLD, NEW_HIGH, M_BREAKOUT_TEST, PREV_HIGH_APPROACH, LEADER_TREND 또는 미모사 종가베팅 감시 상태가 겹치는 경우.
- **수렴·눌림**: M_CONTRACTION 또는 PULLBACK_INTACT 상태.
- **과대낙폭·낙주 반등**: OVERSOLD_WATCH / OVERSOLD_REBOUND_WATCH / FALLING_WATCH / FALLING_REBOUND_WATCH 상태.
- **재료+거래대금**: 최근 인용 포함 재료보고서가 있고 재료유형이 미확인이 아니며, 거래속도·최근구간 대금·테마비중 중 하나가 동반되는 경우.

한 종목은 여러 유형 태그를 가질 수 있지만 카드의 기본 분류는 하나만 사용해 중복 노출을 줄인다. 과대낙폭·낙주 반등 → 추세·돌파 → 수렴·눌림 → 재료+거래대금 순으로 기본 유형을 정하며, 이 순서는 투자매력 순위가 아니라 화면 중복 제거 규칙이다. 네 유형 중 어느 것도 확인되지 않으면 `조건 미완성`으로 남긴다. 화면의 필터 버튼으로 각 유형만 따로 볼 수 있다.

## 후보 생존력 추적

`candidate_tracker.py`는 최신 시장 샘플마다 최대 12개 관찰후보를 로컬 DB의 `radar_candidate_history`에 저장한다. 같은 시장 샘플은 기본키로 중복 저장하지 않으며 14일보다 오래된 후보 이력은 정리한다. 이 작업기는 OpenAI, 주문 API, Telegram 원문을 호출하지 않는다.

현재 후보에는 다음 이력이 붙는다.

- **신규**: 오늘 후보 이력에 아직 저장된 이전 노출이 없는 경우.
- **재진입**: 이전 노출 이후 120초 넘는 공백을 두고 다시 후보가 된 경우.
- **연속 유지**: 75초 이내 간격으로 최소 5회 연속 후보에 남은 경우.
- **강화 / 약화**: 연속 유지 상태에서 약 5분 전 관찰도와 비교해 ±10점 이상 변한 경우.
- **유지**: 위 조건 전의 짧은 연속 노출.

각 카드에는 연속 노출 횟수·분, 최근 15분/30분 후보 노출 횟수, 약 5분 관찰도 변화, 최근 관찰도 스파크라인을 표시한다. 이는 가격 수익률, 체결 수익률, 성공 확률이 아니라 **후보 조건이 얼마나 오래 유지됐는지**를 뜻한다.

현재 후보에서 빠진 종목 중 최근 5분 안에 후보였던 종목은 `최근 후보 이탈`로 표시한다. 후보 이탈은 매도·하락 신호가 아니라 현재 Top 관찰후보 기준을 더 이상 충족하지 않는다는 뜻이다.

또 최근 30분의 후보 이력을 시장테마별로 묶어 `후보군 지속 / 후보군 강화 / 후보군 약화 / 최근 후보군 이탈`을 보여준다. 이 값은 최대 12개 Top 관찰후보의 이력에 기반하므로 전체 시장 테마 강도와 동일하지 않다.

## 후보 성과 저널

후보 생존력과 별도로 `radar_candidate_episodes` / `radar_candidate_outcomes`에 **전향적 관찰 에피소드**를 기록한다. 기능 배포 이전의 과거 후보를 소급해서 만들지 않는다.

후보가 Top 관찰목록에 새로 들어오면 에피소드가 시작되고, 빠지면 종료한다. 다시 들어오면 새 에피소드다. 시작 가격은 그 후보가 실제로 관측된 시점의 SOR 참조가격이며 매수 체결가가 아니다.

각 에피소드에서 +5분 / +15분 / +30분 이후 첫 유효 SOR 관측가격을 고정하고 다음 값을 기록한다.

- 해당 시점 관측수익률: 시작 참조가격 대비 변화율.
- MFE: 시작 이후 해당 시간창 안에서 관측된 최대 상승폭.
- MAE: 시작 이후 해당 시간창 안에서 관측된 최대 하락폭.
- 후보 이탈 시점 참조가격과 변화율.

목표시간 이후 90초 안에 유효 관측값이 없으면 `NO_SAMPLE`로 남겨 임의 보간하지 않는다. 장 종료, 피드 중단, 표본 이탈 때문에 데이터가 없을 수 있다.

화면의 유형별 요약은 후보버전과 기본 유형별로 30일 관측을 묶어 중앙값과 양(+) 관측 비율을 보여준다. 15분 완료 표본이 10건 미만이면 `소표본 · 해석 보류`를 붙인다. 유형별 수치는 투자매력 순위나 미래 확률이 아니다.

수수료, 세금, 슬리피지, 호가잔량, 주문체결 가능성을 반영하지 않으므로 실제 매매손익으로 읽으면 안 된다. 이 저널의 목적은 `관찰도`와 후보 유형이 실제 장중 가격경로에서 어떤 특성을 보였는지 교정하기 위한 데이터 축적이다.

## 종목 차트

조회순위·거래대금 표 및 흐름 데스크에서 차트를 연다. 저장된 KRX 3분봉·일봉, 거래량, 20봉 평균, 일봉의 직전 최대 60일 고가를 표시한다. 전체 기간 신고가로 부르지 않는다. 시점과 미완성 가능 봉을 표시한다. 차트와 금액은 서로 다른 거래소 범위를 혼용하지 않고 구분한다.

버튼을 누르면 해당 종목을 차트 수집 우선목록에 등록한다(최근 선택 6종목 + 순위 상위, 한 주기 최대20종목). 수집 밖 종목은 다음 chart-feed 주기 이후 데이터가 생길 수 있다. 자료가 없을 때 가상 차트로 채우지 않는다. 원래 미모사 상태는 별도 검증 전 규칙 판독으로 표시한다.

## 적용

```bash
(
  set -e
  cd "$HOME/Kiwoom-REST-API"
  git -c core.fileMode=false pull --ff-only
  cd market_radar/local
  bash update_flow_desk.sh --auto
)
```

--auto는 기존 .env에서 WEB_RESEARCH_AUTO만 1로 변경한다. 일일·시간당 한도가 명시되지 않았다면 변경을 중단한다. 키와 한도, 시도 기록은 바꾸지 않는다. 이 명령은 현재 사용자가 요청한 자동 조사 켜기이므로 유료 외부 API가 기존 한도 내에서 실행될 수 있다. 자동을 켜지 않고 화면만 적용하려면 --auto를 제외한다.

Postgres와 Telegram은 재시작하지 않고 흐름·뉴스·테마·차트·대시보드·웹조사·후보추적 관련 서비스만 갱신한다. 처음에는 새 SOR 관측이 2~3회 쌓여야 구간 비교가 나온다. 주말에는 체결시각이 과거인 것이 정상이며 흐름을 가짜로 움직이지 않는다.

## 테스트와 한계

수식·단위·표본 편입/이탈·인증·예산보존을 확인하는 오프라인 테스트 케이스를 저장소에 추가했고, Docker 빌드가 새 Python 모듈을 py_compile 하도록 했다. flow_ui.js는 저장소 반영 전 JavaScript 파싱을 확인했다. 실제 테스트 실행과 서비스 통합 검증은 아래 Mac mini 적용 과정의 Docker build 및 진단 스크립트 결과로 확인해야 한다.

실제 사용자 Mac, 실제 Postgres 쿼리, Kiwoom SOR 응답, OpenAI 유료 성공은 이 개발 환경에서 아직 검증하지 못했다. 사전 테스트는 실제 시세/수익성/미모사 적중률 검증이 아니다. 첫 장중 실행에서 HTS 값과 source/date/venue를 대조해야 한다.
