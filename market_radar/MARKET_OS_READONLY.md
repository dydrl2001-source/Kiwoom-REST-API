# Market OS 실제 수급·계좌 읽기 전용 연결

공식 Kiwoom API에서 실제 데이터를 읽고 기존 Daily Decision/Execution Risk의 관측값을 보강한다.
이 모듈에는 매수·매도·정정·취소 구현이 없고 모든 결과의 `live_auto_execution`은 false다.
실제 자동매매를 활성화하지 않는다.

## 인증과 실행

```dotenv
KIWOOM_MODE=real
APP_KEY=발급받은_실전_앱키
APP_SECRET=발급받은_실전_시크릿
MARKET_OS_READONLY_ENABLED=1
DASHBOARD_TOKEN=기존_대시보드_토큰
```

키는 기존 로컬 `.env`에만 보관하고 git/채팅/로그에 넣지 않는다. 모의 계좌는 `KIWOOM_MODE=mock`과
별도의 `APP_KEY_MOCK`/`APP_SECRET_MOCK`을 사용한다. `demo`에서는 커넥터를 호출할 수 없다.
도메인은 코드에서 공식 실전/모의 도메인으로 고정하고 리디렉션을 따르지 않는다.
외부에서 입력한 URL 또는 API ID로 요청하지 않는다. 허용 목록은 아래 다섯 조회 API뿐이다.

로컬 Compose 서비스:

```sh
cd market_radar/local
docker compose up -d --build --no-deps market-os-readonly
```

기존 PostgreSQL이 실행 중이어야 한다. 별도 화면은 `http://127.0.0.1:8081/market-os/decision`이며
기존 대시보드 토큰으로 인증한다. 기본 바인딩은 로컬 루프백이다. 원격 공개하지 않는다.
`실제 수급·계좌 읽기 전용 연결`에서 종목코드를 최대 5개 입력하고 새로 조회한다.
저장된 결과를 보는 버튼은 증권사 API를 호출하지 않는다. 자동 폴링·자동 주문은 없다.

기존 `radar-api`를 이 버전으로 재배포하면 같은 경로가 주 대시보드에도 등록된다.
구버전 수집기/AI worker의 일괄 교체는 별도 작업이며 이 서비스의 실행과 구별한다.

## 조회 API와 데이터 계약

| API | 요청 | 사용 범위 |
|---|---|---|
| ka10059 | 종목, 날짜, 금액=1, 순매수=0 | 외국인/기관 순매수 백만원 × 1,000,000 → 원 |
| kt00018 | qry_tp=1, dmst_stex_tp=KRX | 추정자산, 평가금액, 누적 평가손익, 대출, 보유종목 수 |
| ka10074 | 시작일=종료일=현재 KST 날짜 | 일치하는 날짜의 실현손익만 사용 |
| ka10075 | 전체종목, 매매전체, 통합시장 | 전체 페이지를 읽어 미체결 수와 종목코드만 보존 |
| kt00017 | 현재 계좌 | D+2 추정예수금 |

금액의 부호를 보존한다. 누락, 빈 문자열, NaN, 무한값은 0으로 대체하지 않는다.
수급은 반환된 날짜 중 요청일 이하 가장 최근 행을 선택한다. 최신 페이지는 과거 전체 이력을 의미하지 않는다.
수급 `as_of`는 원본 날짜, `fetched_at`은 관측 시작 시각이다. 이전 거래일 자료는
`PRIOR_SESSION_CONTEXT`, 같은 날짜도 `CURRENT_DATE_CONTEXT`일 뿐 장중 확정/실시간 트리거가 아니다.

계좌별 당일 실현손익의 행이 없거나 이전 거래일 행만 있으면 금액을 미확인으로 둔다.
D+2 추정예수금은 당장 주문 가능한 금액이 아니다. KRX 평가 범위를 전체 자산군 평가로 확대 해석하지 않는다.

연속조회는 최대 10페이지다. continuation 헤더가 없거나 잘못되거나 next-key 반복/누락/페이지 한도를
만나면 불완전 조회로 실패한다. 이 경우 `unfilled_complete`를 설정하지 않고 중복주문 판정을 UNKNOWN으로 유지한다.
조회 완료 시에도 관측값이 90초를 넘으면 위험 게이트의 중복주문 판단은 UNKNOWN이다.

## 위험 게이트 연결 및 남은 미확인 사실

`enrich_payload`가 일일 패킷 생성·미리보기·검토 intent 생성/확인에 다음만 전달한다.

- 공개 수급 사실: 날짜, 외국인/기관 순매수, 공식 API 출처.
- 계좌 위험 사실: 관측시각, 미체결 전체 조회시각, 해당 종목 중복주문 여부.

계좌 금액, 계좌번호, 주문번호는 AI 패킷에 포함하지 않는다. 계좌번호/주문번호는 DB에도 저장하지 않는다.
PostgreSQL `market_os_readonly_context`에 최신 최소 요약 한 개만 저장한다. 보호된 화면은 `no-store`로 제공한다.
조회 오류는 응답 원문 대신 고정 오류코드만 기록한다.

`daily_loss_pct`는 **항상 미확인**이다. 기존 누적 평가손익/실현손익을 이용해 임의 일일 손실률을 만들지 않는다.
검증된 전일말/당일초 순자산과 장중 입출금·입출고 조정의 완전한 기준이 필요하다.
공식 거래일/세션, 기준 매수가, 손절가, 테마 지속성 등도 확인되지 않으면 계속 차단한다.
실제 API 연결 성공은 자동매매 준비 완료를 의미하지 않는다.

## 호출량과 장애

- 자동 조회 없음. 인증된 사용자의 POST 요청만 실조회한다.
- 요청 간 최소 0.3초, 전체 refresh 최소 30초, PostgreSQL advisory lock으로 동시 refresh 차단.
- 종목 최대 5개. 외국인/기관 조회 각 1페이지, 계좌의 리스트는 완결 여부를 검증한다.
- 실패한 호출을 자동 재시도하지 않는다. timeout/인증/통신/응답 형식 오류는 고정 상태로 표시한다.
- 키움의 실제 계정별 제한은 공식 안내/콘솔이 우선이다. 이 내부 제한은 서버 쿼터를 보장하지 않는다.
- OpenAI 연결 점검은 `GET /v1/models`로 인증만 검사했다. 생성 요청·유료 사용 가능성까지 검증한 것은 아니다.
- 네이버 공식 검색은 별도 키가 있어야 한다. Hub/legacy 인증과 약관·쿼터는 `MARKET_OS_DAILY_DECISION.md` 참고.

## 검증

`tests/test_market_os_readonly.py`는 주문 API 차단, 공식 도메인 고정, 리디렉션 차단,
연속조회 누락/반복/초과, 미래 수급 제외, 백만원 단위 변환, 민감 식별자 제거,
미확인 실현손익, 신선도, AI whitelist 및 HTTP 인증을 검증한다.
실제 연결 결과는 개인 금액/키 없이 별도 연결 상태 보고서에 기록한다.
